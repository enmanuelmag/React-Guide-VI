Responsabilidad pendiente

¿Quién recuerda la respuesta mientras la pantalla cambia?

El fetcher entrega datos una vez. La interfaz necesita conocer si la búsqueda está esperando, cargando, falló o terminó.

TanStack Query administra el estado remoto.React conserva el estado local de la interacción.
Dejar responder antes de revelar. “Estado remoto” significa datos que pertenecen al servidor y llegan de forma asíncrona.

Anatomía de una query

La identidad y el trabajo forman una consulta

queryKeyIdentidadDistingue qué datos estamos consultando.
+
queryFnTrabajoIndica cómo obtener esos datos.
=
QueryUna consulta remota administrada.

Query: consulta identificada que TanStack Query puede ejecutar, observar y almacenar temporalmente.

Pronunciar key como “clave” y query function como “función de consulta”. No introducir opciones adicionales todavía.

La key describe los datos

Si cambia la búsqueda, también debe cambiar su identidad

Identidad incompleta
queryKey: ["media", "search"]

No distingue Dune de otras búsquedas.

Identidad completa
queryKey: [
  "media",
  "search",
  { query: "Dune", mediaType: "movie" },
]

Incluye cada valor usado por la función.

La documentación de TanStack Query indica que cada variable usada dentro de queryFn debe formar parte de la query key.

Mismo texto, datos diferentes

Dune película y Dune serie necesitan entradas distintas

Consulta A["media", "search", { query: "Dune", mediaType: "movie" }]Dune · película
Consulta B["media", "search", { query: "Dune", mediaType: "series" }]Dune · serie

El orden de los elementos del array forma parte de la identidad; las propiedades de un objeto se comparan de forma determinista.

Pedir identificar el único valor que cambia. La caché puede conservar ambas respuestas porque tienen query keys diferentes.

Ventana de frescura

staleTime decide cuándo una respuesta deja de considerarse reciente

0:00Respuesta recibidaDune queda fresh.
2:30Consulta reutilizadaSigue fresh; no necesita otra petición.
5:00Tiempo cumplidoPasa a stale; puede actualizarse después.

Fresh: reciente. Stale: desactualizada según la política, no necesariamente incorrecta.

No decir que stale borra la respuesta. Solo cambia si TanStack Query considera necesario actualizarla ante ciertos disparadores.

query.data es el campo del resultado de useQuery que contiene la respuesta exitosa.

useQuery devuelve query; query.data contiene el array de DTOs cuando la consulta tiene éxito. El adapter visual transforma cada elemento, pero no ejecuta el request ni decide el layout.

query.data viene del resultado de useQuery

Las tarjetas se derivan de query.data; no se copian a otro estado

Derivar durante el render
const mediaItems =
  (query.data ?? []).map(toMediaItem)

Siempre refleja la respuesta actual.

Duplicar en useState
useEffect(() => {
  setMediaItems(query.data)
}, [query.data])

Crea dos fuentes que pueden desincronizarse.

Recordar que query es el resultado de useMediaSearch y, por dentro, de useQuery. query.data contiene la respuesta exitosa. Estado derivado significa un valor calculable desde ese campo disponible; no necesita useEffect ni un segundo useState.
