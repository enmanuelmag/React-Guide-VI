Dos fallos distintos

Un 404 sí trae response; un fallo de red puede no traerla

Error HTTPstatus: 404

El servidor respondió. fetch() entrega una Response y debemos revisar response.ok.

Error de redTypeError

La solicitud no obtuvo una response utilizable. La Promise de fetch() se rechaza.

Ambos terminan en error para la aplicación, pero dejan evidencia diferente.

Contraste respaldado por MDN Fetch. Evitar decir que fetch lanza por cualquier status no exitoso. La aplicación debe crear explícitamente el error HTTP.

Contrato de transporte

Un DTO conserva la forma que cruza la frontera HTTP

DTO: estructura de datos que viaja entre cliente y servidor.

Conserva nombres del transporte.

Conserva nulabilidad del contrato.

No decide la UI: no define qué datos mostraremos ni cómo los distribuiremos en una tarjeta.

Leer dos campos concretos. DTO no significa componente ni modelo visual. La interfaz remota se construirá en la sesión 08.

Límite de TypeScript

El tipo ayuda al escribir código; el servidor entrega JSON en runtime

Compile timeAntes de ejecutar: TypeScript comprueba que nuestro código respete el type declarado.pnpm build
RuntimeMientras se ejecuta: el navegador recibe el JSON real. TypeScript ya no lo inspecciona.json as MediaSearchItemDto

El cast puede ocultar campos incompatibles.

Hacer una pausa en esta diferencia. Compile time es cuando TypeScript revisa nuestro código antes de ejecutarlo. Runtime es cuando JavaScript ya está funcionando y llega la respuesta real. Aunque el proyecto compile, TypeScript no inspecciona el JSON enviado por el backend. La validación runtime con Zod queda fuera de esta sesión.

Un cambio fuera de nuestro código

Compilar bien no garantiza que el JSON tenga la forma esperada

01 · Nuestro type espera 
type MediaSearchItemDto = {
  title: string
  coverUrl: string | null
}

TypeScript conoce esta declaración local.

pero el backend responde
02 · El JSON real trae 
{
  "title": "Dune",
  "cover": "/dune.jpg"
}

coverUrl no existe en la respuesta.

as MediaSearchItemDto no agrega ni transforma coverUrl: durante la ejecución su valor seguirá siendo undefined.

Leer el ejemplo de izquierda a derecha. Nuestro type puede estar bien escrito y el build puede pasar; el backend es otro sistema y puede cambiar su response. Un cast solo cambia lo que TypeScript cree sobre el valor. No revisa el JSON, no renombra cover y no crea coverUrl.
