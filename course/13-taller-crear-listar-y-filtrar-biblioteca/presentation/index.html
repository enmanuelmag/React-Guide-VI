El token autoriza; la key separa respuestas.

Dos responsabilidades

Bearer: el token viaja en la petición; el servidor lo verifica.

authScope: etiqueta la caché con anónimo o el uid del usuario.

authScope no es una credencial. El token nunca se guarda en la query key.

El ejemplo hace visible la explicación sin una segunda diapositiva. Ana y Luis son etiquetas ilustrativas. uid es el identificador de Firebase. Preguntar si alguien puede autenticarse con el uid que ve en Devtools: no. Los valores que cambian la respuesta deben estar en la key. Fuente: https://tanstack.com/query/latest/docs/framework/react/guides/query-keys.

Invalidar: volver a consultar lo que está en uso.

Query activa

Una pantalla montada la está usando.

Se marca desactualizada y vuelve a consultar.

Query inactiva

Está en caché, sin una pantalla que la use.

Se marca desactualizada; espera su próximo uso.

Comportamiento habitual al invalidar: refetch de queries activas y habilitadas.

Al invalidar, las queries activas y habilitadas vuelven a consultar normalmente; las inactivas permanecen marcadas como desactualizadas. Una query con enabled false no participa en ese refetch automático. Un fallo de red puede impedir renovar la respuesta y no revierte una creación que el servidor ya aceptó.
