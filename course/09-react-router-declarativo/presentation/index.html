Definir Router como el componente que observa la ubicación y resuelve rutas. La SPA conserva el documento actual, pero la URL sí puede cambiar.

Responsabilidades separadas

React Router

Relaciona URL, historial y página activa.

Agregar Router no reemplaza useMediaSearch() ni cambia sus query keys.

Dos formas distintas

El patrón nombra posiciones; la URL real contiene valores

Patrón declarado/media/:mediaType/:externalIdLos nombres con : indican segmentos dinámicos.

Ruta: relación entre un patrón de URL y el elemento que React debe renderizar.

Recorrer ambos textos de izquierda a derecha. Evitar llamar params a los nombres del patrón y a los valores concretos como si fueran lo mismo.

Wildcard: patrón * que recibe una URL sin otra coincidencia dentro de este árbol.

Una Route relaciona patrón y elemento. El árbol es declarativo porque describe el resultado esperado para cada ubicación en lugar de cambiar componentes con ifs dispersos.

Estructura compartida

Layout route: ruta padre que comparte estructura con sus hijas sin agregar por sí sola texto al pathname.

La URL no contiene “public-layout”. El layout pertenece al árbol de elementos, no a la forma del pathname.

Fallo controlado

Lo que sí vemosAppHeaderPublicLayout coincidió y se renderizó.

Preguntar: “La URL coincide con /search y aparece AppHeader, pero SearchPage no se muestra. ¿Qué falta dentro de PublicLayout?”. Respuesta esperada: Outlet.

Región para la ruta hija

Outlet marca dónde React Router coloca la página coincidente

LayoutConserva la estructura común.
Página hijaEl árbol la entrega a Outlet.

Outlet no recibe la página como prop y no representa el wildcard.

Outlet es la región de renderizado de las rutas hijas. El elemento concreto viene de la coincidencia actual declarada en App.

Matching: comparación entre la URL actual y los patrones declarados para elegir una ruta.

La coincidencia solo demuestra que la forma del pathname encaja. Todavía no demuestra que movie sea un MediaType válido.

Resultado devuelto por useParams

params contiene los strings capturados desde la URL

Objeto devuelto por useParams(){ mediaType: "movie", externalId: "123" }

Route params: objeto de strings posiblemente ausentes que React Router captura desde segmentos dinámicos.

Señalar primero la invocación completa. params no es un objeto inventado por el componente: useParams lo construye desde la URL coincidente. Distinguir el tipo estático, string o undefined, del valor concreto observado en este ejemplo.

La URL es una entrada externa

Coincidir con el patrón no convierte un string en MediaType

La ruta sí coincide/media/anime/123El patrón acepta texto en :mediaType.
El dominio lo rechazamediaType: "anime"Medialog solo acepta movie o series.

El Router valida la forma de la URL. El adapter valida si sus valores pertenecen al dominio.

“Externo” significa que la persona puede escribir o modificar la URL. La coincidencia sintáctica y la validez del dominio son preguntas distintas.

Adapter: función pura que traduce una forma de datos a otra y rechaza entradas incompatibles.

Entregar esta matriz antes de implementar. Cada fila debe convertirse después en un test. La slide define comportamiento, pero no muestra la función completa.

Validación durante la ejecución

Una assertion cambia lo que TypeScript cree; no revisa la URL

Forma incorrecta
const mediaType =
  params.mediaType as MediaType

"anime" atraviesa la línea sin ninguna comprobación.

Validación explícita
if (
  params.mediaType !== "movie" &&
  params.mediaType !== "series"
) return null

Solo los dos valores conocidos entran al dominio.

Recordar compile time y runtime. as solo afecta la revisión del código; no inspecciona el string recibido mientras la aplicación funciona.
