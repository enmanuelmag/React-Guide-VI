El evento describe lo ocurrido; la aplicación decide qué hacer con esa información.

Señalar que React no inventa la escritura. El navegador produce el evento del input y React ejecuta la función que entregamos en onChange.

Intento que no resuelve la interfaz

Cambiar una variable local no solicita otro render

1 La variable cambia

function App() {
  let query = ''

  function handleChange(event) {
    query = event.currentTarget.value
  }
}

JavaScript guarda el texto solo dentro de esa ejecución de App.

2 La interfaz no cambia

Texto que React conoce: vacío

Nadie solicitó otro render y la siguiente ejecución volvería a crear la variable.

Escribir en el input nativo puede cambiar lo que se ve dentro del campo, pero el párrafo y la colección de React no reciben una nueva versión de query. Esta variable temporal no queda en el checkpoint.

Definir Hook como función de React cuyo nombre comienza con use y permite usar capacidades como estado. Definir setter sin decir que cambia query de inmediato: solicita un render con el nuevo valor.

Estado como snapshot

Cada render trabaja con una versión concreta de query

Snapshot: valores de props y estado disponibles durante un render concreto.

Render 1query === ''La interfaz muestra la búsqueda vacía.
setQuery('a')solicita el siguiente render
Render 2query === 'a'La nueva interfaz usa “a”.
Seguir el orden de izquierda a derecha. El setter no reescribe el snapshot del render 1; prepara el render 2, que recibe otra versión de query.

Los Hooks se declaran siempre en el nivel superior

React necesita encontrar los Hooks en el mismo orden durante cada render.

✓ Orden estable

function App() {
  const [query, setQuery] = useState('')

  return <main>...</main>
}

El Hook se ejecuta en cada render de App.

! Orden variable

if (showSearch) {
  const [query, setQuery] = useState('')
}

La condición puede omitir el Hook y cambiar el orden.

No abrir todavía reglas avanzadas. La regla operativa de hoy es declarar useState directamente dentro de App, antes de condiciones, handlers o recorridos.

El circuito funciona porque value y onChange apuntan a la misma fuente de verdad.

Definir fuente de verdad como el componente que conserva la versión autoritativa del dato. En esta sesión es App. No decir que onChange actualiza de forma síncrona el DOM de React; solicita la actualización.

App conserva query; SearchInput comunica un nuevo texto

SearchInputLee el evento y entrega un string.
AppConserva query y entrega el setter.

Prop de callback: función que un padre entrega para que un hijo comunique una acción.

Seguir la ruta del string: el hijo lee currentTarget.value y llama onQueryChange; App entregó setQuery como esa función. El evento DOM no cruza el límite del componente.
