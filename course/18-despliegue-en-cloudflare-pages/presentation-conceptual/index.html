MediaLog / Despliegue web

La “cloud” usa computadoras del proveedor.

Hosting: servicio que conserva y entrega los archivos de tu web mediante una URL pública.

La nube no es un lugar mágico: es infraestructura física administrada por un proveedor. localhost siempre se refiere al equipo que hace la petición. Compartir localhost no comparte tu computadora. Después del despliegue, apagar tu portátil no apaga los archivos alojados. No afirmar que todo hosting es una sola máquina ni que la nube solo sirve archivos.

El pipeline ejecuta una receta automática.

Pipeline = pasos automáticos en un orden definido. Pages puede ejecutarlos al recibir cambios de Git.

La integración Git de Pages es el ejemplo, no asumimos GitHub Actions ni un YAML obligatorio. Instala, ejecuta el comando de build y publica la salida configurada. MediaLog / Despliegue web

Una CDN acerca copias de los archivos.

La red dirige la petición a un nodo adecuado. Hosting + CDN vienen integrados en Cloudflare Pages.

CDN significa Content Delivery Network. Un nodo es un punto de esa red. Dibujo conceptual, no geografía ni topología real de Cloudflare. Suele reducir distancia y carga del origen, sin garantizar que siempre use el nodo físicamente más cercano. Hosting conserva contenido; la CDN puede guardar copias reutilizables. No significa que cada despliegue copie de inmediato todos los archivos a todos los nodos. Fuentes: https://www.cloudflare.com/learning/cdn/what-is-a-cdn/ y https://www.cloudflare.com/learning/cdn/glossary/edge-server/

La CDN reutiliza una copia cuando puede.

Caché = copia temporal para reutilizar. Si falta o necesita validarse, puede consultarse al origen.

En la fila superior el nodo obtiene el archivo, lo devuelve al navegador y puede conservarlo según las reglas de caché. Esta es una explicación general, no el detalle interno exacto de Pages. Caducar no significa borrar inmediatamente: puede requerirse revalidación. Distinguir esta caché de archivos de TanStack Query, que conserva respuestas para la app, y de la caché HTTP del propio navegador. Fuente: https://www.cloudflare.com/learning/cdn/performance/

La URL permite encontrar y pedir la web.

DNS relaciona el nombre con una dirección de red. HTTPS protege la comunicación.

URL ilustrativa, no un despliegue creado. Primero el navegador resuelve el dominio, posiblemente usando una caché; después establece la conexión segura y envía la petición HTTP. No presentar DNS como algo que entrega HTML ni como el sistema que elige componentes React. Simplificamos los intermediarios y la negociación TLS. El hosting/CDN atiende la petición, no el repositorio Git.

MediaLog / Despliegue web

En CSR, React dibuja dentro del navegador.

CSR = renderizado del lado del cliente: el JavaScript de la app construye la interfaz en el navegador.

En nuestra SPA sin SSR, index.html aporta la entrada y referencias a recursos; no contiene toda la interfaz React ya renderizada. El navegador pide recursos, procesa CSS y ejecuta JavaScript; React monta los componentes. No afirmar que HTML está completamente vacío ni que todo JavaScript necesariamente llega en una única descarga. El build ocurre antes; el render ocurre en cada navegador.

MediaLog / Despliegue web

Cambiar el código requiere publicar otra versión.

Los nombres versionados ayudan a distinguir archivos nuevos de copias anteriores.

app-a1.js y app-b2.js ilustran hashes de contenido. Un despliegue no reescribe el JavaScript que ya está ejecutándose en pestañas abiertas. La obtención de la versión vigente depende de reglas de caché correctas y revalidación del HTML; no prometer propagación instantánea ni un temporizador universal. Esta app no introduce un service worker. Pages gestiona publicación y caché de sus assets; no pedir purgas manuales como paso obligatorio.
